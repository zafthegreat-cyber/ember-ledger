## 5. Supabase (project gxsfququorfczvhrkudl)

### Security advisors
- **20 × RLS enabled, no policy** — all in `code3_alerts`, `code3_ebay_private`, `code3_private`, `code3_submissions`. These schemas are not exposed through PostgREST and are written by service-role functions, so "no policy" means "no client access", which is the intent. No action, but keep them out of the exposed schema list.
- **5 × SECURITY DEFINER callable by `anon`**: `can_edit_workspace`, `can_manage_workspace`, `can_read_workspace`, `workspace_role_for`, `sync_workspace_member_from_membership`. The four `can_*`/`role_for` helpers only return booleans/roles for the caller's own JWT, so exposure is low, but there is no reason for `anon` to call them: `REVOKE EXECUTE ... FROM anon` is a safe one-line fix each. `sync_workspace_member_from_membership()` is a trigger function and should not be executable via RPC at all — revoke from `anon` and `authenticated`.
- **15 × SECURITY DEFINER callable by `authenticated`**: the `admin_*` functions check the admin role internally (the role-management tests cover this) and the invite/workspace functions are meant for signed-in users. Acceptable; document the internal checks.
- **3 × mutable `search_path`**: `beta_invite_status`, `set_updated_at`, `normalized_app_role` — add `SET search_path = public, pg_temp` to each definition.
- **Leaked password protection disabled** — turn on in Auth settings (free; blocks known-breached passwords at sign-up).

### Performance advisors
- 44 policies re-evaluate `auth.uid()`/`current_setting()` per row → wrap as `(select auth.uid())`. Cheap, mechanical, worth a migration before the user count grows.
- 166 multiple-permissive-policy warnings, mostly `anon` + owner + admin policies on the same table/action. Harmless today; consolidate when touching those tables.
- 84 unindexed foreign keys (82 in `public`), 143 unused indexes. Low priority at beta scale.
- Auth DB connections: default absolute setting flagged; revisit if the pooler saturates.

### Applied the same day (migrations `audit_2026_11_14_function_hardening`, `audit_2026_11_14_rls_initplan`, `audit_2026_11_14_trigger_fn_public_revoke`)
- `anon` EXECUTE revoked on `can_edit_workspace`, `can_manage_workspace`, `can_read_workspace`, `workspace_role_for` (every policy that calls them is `authenticated`-only, verified before revoking).
- `sync_workspace_member_from_membership()` and `set_updated_at()` revoked from `anon`, `authenticated` and `PUBLIC` — triggers still fire as the table owner.
- `search_path = public, pg_temp` pinned on `beta_invite_status`, `set_updated_at`, `normalized_app_role`.
- All 44 flagged RLS policies rewritten to `(select auth.uid())` / `(select current_setting(...))`; expressions otherwise identical.

Still open and dashboard-only: **leaked password protection** (Authentication → Settings → Password strength). The 15 `authenticated`-callable SECURITY DEFINER functions are intentional (admin checks are inside them).
